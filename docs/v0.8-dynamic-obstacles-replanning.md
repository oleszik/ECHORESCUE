# v0.8 — Dynamic Obstacles and Dynamic Replanning

## Motivation and architecture audit

v0.8 asks how EchoRescue reacts when traversability changes after planning. The
pre-implementation audit found that `GridWorld.walls` was immutable and motion
treated any unexpected occupied Ground-Truth destination as a collision. That
was the principal static-world assumption. Cached exploration and return paths
could therefore become stale without a structural event describing why.

Several components already had the right behavior. `OccupancyMap.update`
accepts a later `FREE → OCCUPIED` observation. Timestamped `KnowledgeMap`
records allow newer observations to replace older evidence, while their
safety-first merge makes `OCCUPIED` dominate conflicting `FREE` reports. A*
already reads a map abstraction, frontier allocation preserves a reachable
current target and otherwise chooses a deterministic replacement, and the RTB
planner already recalculates route energy and has `RETURN_PATH_UNAVAILABLE` and
energy-emergency states. The N-agent deconfliction, battery physics,
communication/Relay transport, Survivor perception, and failure reassignment
did not need new algorithms.

The minimal change is a mutable dynamic-closure layer on otherwise immutable
generated geometry, observation-driven path invalidation, explicit replan
state and telemetry, and a last-resort stale-path safety intervention.

## Dynamic-obstacle and injection model

Dynamic obstacles are opt-in. `off` is the default and retains byte-identical
legacy replay output. `moderate` schedules two persistent `FREE → OCCUPIED`
closures at steps 12 and 30. Candidate cells are derived only from the seed and
initial map: deterministic base-to-cell A* centrality, with a stable hash for
ties. The selector excludes the base, Survivors, agent starts, cells within
Manhattan distance 3 of the base or another selected closure, and any cell
whose removal disconnects the initially traversable interior. It never reads
current or future agent paths.

Explicit injection uses `--inject-obstacle X,Y:STEP` and is repeatable. It is
mutually exclusive with a profile. Validation rejects boundary/out-of-map
cells, the base, configured starts, duplicate locations, and steps outside
`1..max_steps-1`; world construction additionally rejects initial walls and
Survivor cells. If an agent occupies the requested cell at the event instant,
the environment records a rejected event and leaves the cell free. Accepted
closures persist for the rest of the mission; reopening is outside this slice.

Internal injection events carry step, position, cause, and old/new cell state.
They remain evaluator telemetry and are deliberately omitted from ordinary
operator replay, because showing an unobserved closure would leak Ground Truth.

## Ground Truth, observation, and map conflict semantics

Injection changes only `GridWorld.dynamic_obstacles`. It does not update an
agent map. A distance-sensor observation later reports the cell occupied, at
which point the observer's timestamped local map and, in shared mode, the fleet
occupancy map update. Replay frames expose only the accumulated
`dynamic_obstacles_observed` set.

A newer unequivocal occupied observation may overwrite earlier free evidence:
traversability is time-varying, so retaining stale `FREE` would be unsafe.
Knowledge synchronization remains safety-first. Once any source has observed a
closure, `OCCUPIED` wins against conflicting free reports even when a stale
free record has a later transport timestamp. This intentionally supports
closures only; a future reopening model would require a distinct versioned
state transition policy.

## Path invalidation and deterministic replanning

After a legitimate observation, every affected shared-knowledge path is
checked, not only its next cell. A blockage anywhere in `planned_path[1:]` or
`current_return_path[1:]` emits `path_invalidated` and `replan_requested` with
the remaining old length. Local mode applies the trigger to the observer;
normal local allocation and synchronization behavior remains intact.

Exploration replanning follows the existing deterministic allocator:

1. Preserve the current target if it is still a valid, uniquely owned frontier
   and A* finds a route on current knowledge.
2. Otherwise release/invalidate it and select the globally ordered reachable
   replacement frontier.
3. Emit success, failure, unreachable, and reassignment events with compact
   old/new length context.

The allocator continues to own reservation and failure-reassignment semantics,
so no stale parallel task system or two-agent special case was introduced. A
failed frontier replan does not itself fail the mission; other reachable work
can continue.

RTB uses the same invalidation trigger. It recomputes a known-free path to base,
updates the return-energy estimate from that path, and preserves the existing
early-return reserve decision. If no safe path exists it enters the existing
`RETURN_PATH_UNAVAILABLE` state—there is no teleport or traversal through the
closure. If stale knowledge nevertheless produces a move into a newly blocked
Ground-Truth cell, the safety shield prevents movement, creates a contact
occupancy observation, records `stale_path_safety_intervention`, and requests a
replan. Such an intervention is not counted as a wall collision.

## Telemetry, replay, and dashboard

The event vocabulary adds injection/rejection (internal), observation, path
invalidation, replan request/success/failure, target unreachable/reassigned,
and stale-path safety intervention. Dynamic results contain injection,
observation, invalidation, replan, target, RTB, shield, and projected path-delta
counts. The per-run mission-duration counterfactual is `null` because a single
mission cannot know its paired baseline; the benchmark supplies the exact
paired value.

Replay schema 2.2 adds the structurally observed blockage layer. Legacy replay
schemas and dynamic-off bytes remain unchanged. The dashboard draws observed
closures with an orange marker and distinguishes blockage/replan events in its
event feed. It can also summarize the paired benchmark artifact.

## Development set and frozen profile

Seeds 0–9 were used only to test event frequency and timing before the holdout.
Candidate timings `(4,12)`, `(6,18)`, `(8,24)`, `(10,24)`, and `(12,30)` were
compared on that development set. Steps 12 and 30 were frozen because they allow
meaningful exploration before each event while still producing genuine route
effects. With the frozen rule all 20 closures were injected and observed; 4/10
missions had path invalidations (9 total), all missions succeeded, and all were
collision-free. No parameter was changed after examining holdout seeds.

## Paired 50-seed holdout

The committed artifact is
[`dynamic_obstacles_50_holdout_seeds.json`](../benchmarks/dynamic_obstacles_50_holdout_seeds.json).
For every seed 50–99, A uses dynamic obstacles off and B uses `moderate`; all
other settings are identical: two agents, Visual sensing, noise off, Smoke off,
Relay off, ideal/shared knowledge, and no failure. Every dynamic run was
repeated. `±` is population standard deviation; values then show median
`[min,max]`.

| Metric | Off | Moderate | Paired delta |
| --- | ---: | ---: | ---: |
| Mission success | 50/50 (100%) | 50/50 (100%) | 0 seeds changed |
| Survivor Recall | 1.000±.000; 1.000 [1,1] | 1.000±.000; 1.000 [1,1] | 0 seeds changed |
| Mission duration | 70.14±5.73; 69 [60,88] | 73.06±5.51; 72.5 [64,88] | +2.92±2.76; +3 [-2,+11] |
| Total path length | 131.80±8.87; 131 [115,151] | 137.40±8.59; 137 [121,157] | +5.60±3.64; +6 [-2,+14] |
| Dynamic obstacles observed | — | 1.98±.14; 2 [1,2] | — |
| Path invalidations | — | .98±1.05; 1 [0,3] | — |
| Replans | — | .98±1.05; 1 [0,3] | — |

Mean relative overhead is +4.282% duration and +4.319% total path length.
There were 49 path invalidations and 49 successful replans, zero failed
replans, five target invalidations/reassignments, and 38 RTB replans. All 100
dynamic agents returned; wall and drone collisions were both zero. The
per-seed table in the JSON artifact contains absolute/relative deltas, Recall,
success, obstacle observations, invalidations, and replan outcomes for all 50
pairs.

## Per-seed analysis and failure modes

- Largest duration overhead: seed 88 (+11), then 60/81/98 (+8).
- Largest path overhead: seed 99 (+14), then 81/83/84/88 (+12).
- Seventeen seeds had multiple replans. No holdout seed had a replan failure,
  Recall change, or mission-success change.
- Seeds 57 and 80 finished two steps faster. This is a deterministic secondary
  effect of changed frontier/deconfliction timing, not evidence that closures
  improve exploration.
- Every holdout mission observed at least one closure; seed 52 observed one.
  Twenty-three seeds observed closures that did not intersect a cached active
  path, so they correctly recorded no path invalidation.
- The 4-agent regression's seed 1 is the representative benign failure mode:
  one blocked-route frontier became unreachable, the replan failed and released
  the target, other work continued, Recall remained 1.0, all four agents
  returned, and the mission succeeded without collision.

## N-agent regression and controlled stress test

Dynamic tests cover 1, 2, 4, and 8 agents deterministically. The separate
4-agent check uses development seeds 0–9: 10/10 missions succeeded, all 40
agents returned, all 20 closures were observed, there were 45 invalidations,
44 successful replans, one benign failed frontier replan, and zero collisions.

The explicitly labelled `controlled replanning stress test` is the only
path-aware scenario. It creates a known narrow RTB route, closes its next cell
after planning, and verifies that the agent takes the deterministic four-edge
detour. A companion test closes the only route and verifies
`RETURN_PATH_UNAVAILABLE`. These tests are not part of the benchmark baseline.

## Limitations and next research question

The model represents permanent cell closures, not collapse physics, movable
debris, doors, reopening, SLAM correction, dynamic Smoke, or moving Survivors.
The moderate selector is map-aware but deliberately route-unaware. Projected
per-replan path deltas and paired total-path deltas answer different questions
and should not be conflated. The main experiment isolates ideal shared
knowledge; delayed blockage propagation under constrained communication is not
benchmarked here.

v0.8 is complete under its acceptance criteria. The next roadmap question is
v0.9 generalized roles and failure resilience, which is not implemented in
this slice.
