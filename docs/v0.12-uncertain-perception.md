# v0.12: Uncertain perception and probabilistic mapping

## Frozen experiment protocol (before final holdout)

The machine-readable source is [uncertainty_protocol.json](../benchmarks/uncertainty_protocol.json).
Profiles, probability parameters, weight 4, seeds and reporting rules are frozen
in a local commit before executing holdout. Development uses 0,1,2,3; targeted
stress scenarios use 4,5. Earlier benchmarks used 0-99, including repeated
50-99 "holdouts". Those are development history, not fresh validation.
Repository source/docs/artifacts were searched for the new 12000-12019 range;
no prior use was found. This does not assert anything about unrecorded external runs.

Primary matrix: 20 seeds x four profiles x two planners = 160 runs. Each uses
13x9 cells, two agents, three Survivors, maximum 200 ticks, battery 220,
shared knowledge and ideal transport, with other SimulationConfig defaults.
The planning effect is isolated within each profile: same world seed, sensors,
fusion, decay, energy and privileged execution shield. Different trajectories
sample different cells; stateless seed/agent/tick/target sensor keys avoid
random-stream call-order artifacts. Occupancy draws do not include profile,
allowing common random numbers across severity; legacy Survivor keys include
profile but remain identical between planners within each severity.

| Profile | Occupancy detection | Occupancy FP | Occupancy strength | Survivor detection | Survivor FP | Survivor strength |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| clean | 1 | 0 | .95 | 1 | 0 | .95 |
| low_noise | .95 | .02 | .90 | .95 | .02 | .90 |
| medium_noise | .85 | .08 | .80 | .85 | .08 | .80 |
| high_noise | .65 | .20 | .65 | .65 | .20 | .65 |

Detection is sensitivity, FP is a false report given absence, strength is the
log-odds/heuristic increment reliability. False negative occupancy reports free.
Survivor strength applies to positive and negative evidence; negative reduces
score by .55*strength. Confirmation needs two unique positives and score .65;
confirmed and rejected states are latched. Scores are not calibrated probabilities.
No profile is chosen after observing holdout outcomes.

The primary success endpoint is stricter than legacy success: full true Survivor
Recall, all agents returned, zero collisions AND zero false confirmations.
Precision is undefined (JSON null) when no locations are confirmed. Duration of
successful runs is reported separately, and paired successful duration includes
only seeds where both planners succeeded. All failed runs remain in other metrics;
timeout and other failure rates are separate. No survival-time imputation.

Brier score covers every in-bounds cell, including boundary walls, at the final
simulation tick against current world occupancy; unobserved cells use prior .5.
Observed-only Brier and retained-evidence coverage are separate. This coverage
is not traversed-area coverage. Replans count changes to a still-active route
with the same endpoint, excluding ordinary one-cell progress, sampled at frames.
Interventions include deconfliction; unsafe attempts count privileged wall vetoes.

Seed-level mean, sample SD and 95% intervals are stored. Binary rates use Wilson
intervals; other means and paired candidate-minus-naive differences use 2000
seed-resampling percentile bootstrap replicates with seed 912. Paired differences
resample intact pairs. Intervals are exploratory, without multiple-test correction;
small N and rare failures limit inference. Degenerate bootstrap intervals at zero
are not evidence of zero population risk (use Wilson marginal intervals).

Targeted development scenarios (not another holdout) test closure/reopening,
local constrained transport latency 1 versus 8, and three-floor operation.
Conflicting multi-agent evidence and relay loops are additionally controlled
unit/integration experiments. All targeted parameters are in the protocol.

## Architecture and limits

See [ADR 0013](adr/0013-observation-union-probabilistic-mapping.md).
Both planners use identical thresholded maps. The entropy proxy only changes
new frontier ordering; stable targets, floor congestion, role restrictions,
RTB reserves and deconfliction retain priority. It is not a sensor-model-based
expected information gain and cannot justify unsafe movement.

2D local occupancy evidence uses the existing constrained transport, including
fragmentation, latency, loss, TTL, relays and queue limits. One raw evidence item
costs one payload unit. Ideal shared mode observes directly; ideal local sync
unions observations through connected components. Repeated evidence is idempotent.
Survivor confirmations in local mode must first satisfy an individual agent's
tracker; the existing transport forwards detection/confirmation sets, not summed
confidence. Thus two agents' isolated weak hypotheses do not jointly confirm a
find in local mode. Shared mode accumulates unique original agent observations.

2.5D uses the same per-floor occupancy model and Survivor tracker, but retains
v0.11 centralized shared knowledge. Its radio graph is telemetry, not a
multi-floor distributed store-and-forward simulation. The primary transport
comparison is therefore 2D; no claim of distributed multi-floor validation.
Stair endpoints are provided by mission topology, not discovered hidden truth.

Ground-truth execution vetoes remain privileged and are counted. Probabilistic
vetoes inject no truth into the map. Generic path invalidation uses observed
threshold changes, not the true type of an obstacle. Zero collisions alone
therefore do not demonstrate robust perception. Dynamic reopen changes only
the world; the knowledge map must acquire new free evidence or decay to prior.

Occupancy memory is bounded by map cells x source agents x 640 ticks. The
existing transport/log/replay bookkeeping remains bounded by configured mission
length, not a constant-memory streaming service. No physical sensor calibration,
correlated error process, real hardware safety, or v0.13 work is included.

The entropy proxy improves clean-condition duration but does not increase mission
success in any profile. The clean mean is influenced by naive seed 12012
(duration 192, 328 route changes across two agents); it is retained, not removed
as an outlier. Increasing noise sharply reduces return, Recall and map quality.
At high noise uncertainty-aware Recall is **18.33 points lower** (95% paired CI
-33.33 to -5.00), and Brier is **0.04075 worse** (CI +0.02029 to +0.06270).
Its shorter all-run duration reflects early failure, not faster successful rescue.
The study therefore does not support a general robustness advantage for this
local entropy proxy. It would be inappropriate to tune the proxy on these seeds.

## Targeted findings

[Targeted development rows](../benchmarks/uncertainty_targeted.json) include all
16 runs. The closure/reopening scenario succeeds in both naive runs and one of
two uncertainty-aware runs. Reopening changes world truth only; fresh free
observations reverse occupancy confidence, also verified by a controlled test.
For local constrained latency 1 versus 8, all eight missions fail the strict
success endpoint. Seed 5 uncertainty-aware Recall changes from 2/3 to 1 with
latency, whereas most Recall values are unchanged. This small saturated-failure
sample does not establish a reliable latency benefit or harm. It shows why
stale occupancy and incomplete returns must be reported separately from Recall.
Decay/delayed-message unit tests isolate age mathematically without trajectory
confounding: delayed and on-time evidence have identical probability at the same
tick; duplicate receptions do not refresh age, and expiry returns to prior.

Three-floor runs have full true Recall; naive succeeds on both targeted seeds,
uncertainty-aware on neither. This is a stress result, not an independent
holdout or proof of planner superiority. The two-floor repeatable integration
test additionally checks that equal row/column cells on different floors stay
separate. Multi-agent opposing observations cancel to the prior in the controlled
same-tick test, and a real two-hop transport test verifies delay, TTL and duplicate
idempotence.

After the freeze, a reporting-only correction made the 2.5D aggregate Recall
count true confirmed locations, matching its already-correct per-floor Recall.
It does not affect trajectories or the primary 2D holdout. Dashboard text alignment
and the local aggregate overlay were also corrected without simulation changes.

## Validation

- New unit/integration tests: probability bounds, threshold states, conflicting
  evidence, raw union, relay duplicates, age/expiry, reopening, floor identity,
  Survivor duplicate protection, keyed sensor reproducibility, pure-map entropy
  scoring, local tracker separation, and byte-identical uncertain mission replay.
- Full regression: **275 tests passed** in 225.686 seconds. A subsequent
  reporting regression test additionally checks false-positive floor Recall.
- `python -m mypy src`: passed (32 production modules; benchmark aggregators use
  the repository's existing exclusion policy).
- `python -m compileall -q src tests`: passed.
- `node --check src/echorescue/dashboard_assets/app.js`: passed.
- Local dashboard server starts and HTTP responds 200; replay validator and old
  replay regression checks pass. The new fields are optional extensions of the
  existing schemas; off-mode serialized configuration and message hashes retain
  legacy semantics.
- **Visual browser inspection blocked:** the Computer-Use browser entry point
  returned `No browser is available`. No visual QA completion is claimed.

Remaining limitations include noisy current-cell/free-path disconnects causing
conservative return failure, latched rejected Survivor hypotheses, correlated
sensor error not modeled, small holdout N, and the privileged safety shield.
v0.13, push, merge and deployment were not started.

Custom research configurations can use `ProbabilityConfig` through Python, for
example `SimulationConfig(uncertainty_profile="medium_noise",
probability_config=ProbabilityConfig(half_life=40.0))`. Such a change defines a
new experiment; it is not the frozen v0.12 holdout. Occupancy and Survivor sensor
parameters are independently named in `UncertaintyProfile` and the protocol.
