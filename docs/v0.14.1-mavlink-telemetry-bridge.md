# v0.14.1: Receive-only MAVLink-to-ROS 2 telemetry

## Scope and architecture

v0.14.1 adds the smallest real, receive-only telemetry path:

```text
Gazebo Harmonic iris_runway
  <-> ardupilot_gazebo JSON interface
  <-> ArduPilot Copter 4.6.3 SITL
  -> MAVLink TCP 5760
  -> echorescue_mavlink_telemetry_bridge
  -> typed ROS 2 topics
  -> independent echorescue_mavlink_telemetry_observer
```

The bridge does not import or query Gazebo. Its only outgoing MAVLink message is
`REQUEST_DATA_STREAM(MAV_DATA_STREAM_POSITION)` at the configured rate; that is
a telemetry subscription request, not a vehicle command. There is no arming,
takeoff, landing, mode change, waypoint, motion, mission, or acknowledgement
path.

The ROS-independent core is
[`src/echorescue/mavlink_telemetry.py`](../src/echorescue/mavlink_telemetry.py).
It owns immutable values, field/unit parsing, monotonically increasing accepted
sample sequences, source packet ordering, per-message source timestamp checks,
freshness, stale/disconnect transitions, reconnect sessions, and stable JSON
serialization. It imports neither `rclpy` nor `pymavlink` and does not alter the
deterministic simulator or v0.13 state machines.

## Node, topics and contracts

Node: `/echorescue_mavlink_telemetry_bridge`

| Topic | Type | Contents and frame |
| --- | --- | --- |
| `/echorescue/mavlink/vehicle_state` | `echorescue_interfaces/msg/MavlinkVehicleState` | Heartbeat-derived armed state, Copter flight mode, system/component IDs and MAVLink packet sequence; frame `mavlink/autopilot` |
| `/echorescue/mavlink/local_position_ned` | `echorescue_interfaces/msg/MavlinkLocalPositionNed` | north/east/down position in metres and N/E/D velocity in m/s; frame `mavlink/local_ned` |
| `/echorescue/mavlink/global_position` | `echorescue_interfaces/msg/MavlinkGlobalPosition` | WGS84 latitude/longitude in degrees, MSL/relative altitude in metres, N/E/D velocity in m/s and optional heading in degrees; frame `wgs84` |
| `/echorescue/mavlink/status` | `echorescue_interfaces/msg/MavlinkTelemetryStatus` | session, bridge sequence, connection/health state, source time, local receipt time, age, threshold and detail |

Every position message preserves MAVLink `time_boot_ms` as
`source_time_boot_ms`. Every published sample also carries a local monotonic
nanosecond receipt timestamp; its ROS `Header.stamp` is the node-clock receipt
time. Integer `GLOBAL_POSITION_INT` protocol units are converted at the boundary:
degrees E7 to degrees, millimetres to metres, centimetres/second to metres/second,
and centidegrees to degrees. A heading value of 65535 becomes
`has_heading=false`.

Local position is kept in MAVLink NED. Body values would remain FRD, but this
milestone publishes no body-frame measurement. Nothing is converted to Gazebo
ENU or to an EchoRescue continuous target frame.

High-rate vehicle/position topics use best-effort, volatile, keep-last-32 QoS.
Status uses reliable, transient-local, keep-last-1 QoS so an observer joining
late receives the latest health state.

## Health, ordering and reconnect behavior

- `DEGRADED`: heartbeat received, but no accepted local position yet.
- `CONNECTED`: advancing position source time is within the freshness threshold.
- `STALE`: position age is strictly greater than the threshold. Equality remains
  fresh.
- `DISCONNECTED`: no transport, a transport exception, or heartbeat timeout.

Duplicate/out-of-order MAVLink packet sequences, decreasing local receipt times,
and duplicate/decreasing position source timestamps are ignored. Stationary
coordinates remain live when `time_boot_ms` advances. A reconnect creates a new
session ID and resets source ordering; stale data cannot cross sessions.

## Configuration

The versioned contract is
[`config/mavlink-telemetry-v0.14.1.json`](../config/mavlink-telemetry-v0.14.1.json).
Baseline values are:

| Option | Default |
| --- | --- |
| MAVLink endpoint | `tcp:127.0.0.1:5760` |
| Position stream rate | 10 Hz |
| Freshness threshold | 1.0 s |
| Heartbeat disconnect threshold | 3.0 s |
| Reconnect interval | 1.0 s |

All five bridge values are ROS parameters. The endpoint and thresholds can be
overridden with ordinary `--ros-args -p name:=value` arguments.

## Build and startup on native Ubuntu 24.04/Jazzy

The Python environment must contain `pymavlink` and expose system site packages
so it can also import the apt-installed Jazzy modules. Preserve the ROS
`PYTHONPATH` when adding the repository source path; replacing it causes
`ament_package` imports to fail during interface generation.

```bash
source /opt/ros/jazzy/setup.bash
python3 -m venv --system-site-packages .venv-sim
source .venv-sim/bin/activate
python -m pip install -e ".[dev]" MAVProxy pymavlink
export PYTHONPATH="$(pwd)/src${PYTHONPATH:+:$PYTHONPATH}"

cd ros2_ws
python -m colcon build --symlink-install
source install/setup.bash
cd ..

ros2 run echorescue_ros mavlink_telemetry_bridge --ros-args \
  -p endpoint:=tcp:127.0.0.1:5760 \
  -p stream_rate_hz:=10 \
  -p freshness_threshold_s:=1.0
```

Start Gazebo and SITL first using the pinned v0.14.0 environment. The standalone
bridge reconnects after unavailable endpoints and reports disconnected health
while it waits.

## Real integration test

After sourcing Jazzy, `.venv-sim`, the built workspace, and the v0.14.0 Gazebo
environment variables:

```bash
./scripts/run_mavlink_telemetry_integration.sh \
  --output artifacts/v0.14.1-telemetry-smoke.json \
  smoke --timeout 90
```

The harness performs real preflight checks, starts Gazebo, prebuilt SITL, the
bridge, and an independent typed subscriber. It requires the node and all four
typed topics, heartbeat-derived state, global position, at least two local NED
samples with advancing source time, and telemetry age within threshold. It then
terminates every owned process group and verifies UDP 9002/14550 and TCP 5760
are available.

Unavailable external dependencies return `SKIP` with the failed preflight check
names and start no process. Runtime failure, timeout, observer failure, or
interruption returns `FAIL`; bounded log tails are retained beside `--output`.

## Ground Truth and determinism boundaries

The bridge source contains no Gazebo API or world/pose topic. Only the outer
smoke harness checks that the Iris world exists. ArduPilot is the sole telemetry
source. The existing grid simulator retains all exact fingerprints; real
physics timings and ROS receipt timestamps are evaluated as bounded invariants,
not byte-identical outputs.

## Limitations

- Receive-only telemetry is not autonomous flight or evidence of flight safety.
- No commands, command acknowledgements, ENU conversion, continuous EchoRescue
  positions, indoor world, obstacle avoidance, SLAM, perception, multi-vehicle,
  HIL, or real vehicle are included.
- Copter custom-mode labels cover the pinned baseline; unknown numeric modes are
  retained as `UNKNOWN(n)`.
- TCP 5760 is a single configured vehicle endpoint. Multi-vehicle sessions are
  outside this milestone.
