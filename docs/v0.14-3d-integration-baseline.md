# v0.14.0: 3D simulation integration baseline

## Scope

This milestone verifies environment readiness and the official ArduPilot Iris
example. It does **not** implement EchoRescue flight control, takeoff,
waypoints, frame conversion, an indoor world, sensing, avoidance, multi-drone
physics, a replay schema, HIL or real flight.

The versioned contract is
[`config/simulator-stack-v0.14.0.json`](../config/simulator-stack-v0.14.0.json).
The orchestration code uses only the Python standard library until the opt-in
MAVLink probe imports `pymavlink`.

## v0.13 architecture carried forward

v0.13 has two ROS 2 processes and a ROS-independent reference transport:

```text
simulator_node (sole GridWorld / Ground Truth owner)
  -> /echorescue/observations + /echorescue/agent_state
  -> mission_node (local probabilistic map and mission policy)
  -> /echorescue/move_grid action
  -> simulator_node safety check + atomic grid step
  -> actual state confirms the command

mission/status <-> simulator/status heartbeats
```

The immutable contracts and both state machines live in the normal Python
package. ROS packages perform conversion and transport only. Session IDs,
sequence numbers, idempotent command IDs, command leases, watchdogs and
controlled stops handle duplicate, delayed, missing and restarted processes.
The v0.14.0 external scaffold is adjacent to this architecture; it does not
replace the deterministic backend or connect the mission policy to SITL.

## Diagnostic command

Run from a prepared Linux checkout:

```bash
./scripts/run_3d_integration.sh diagnose
```

Save the same deterministic JSON report if desired:

```bash
./scripts/run_3d_integration.sh --output artifacts/v0.14-diagnostic.json diagnose
```

Every check contains `PASS`, `FAIL` or `SKIP`, a detected version where
available, and an actionable detail. `FAIL` exits 1. A rendering `SKIP` does
not claim graphical readiness; it indicates that only headless execution may
be attempted after all required checks pass.

## Native Ubuntu preparation and encountered dependencies

The validated machine uses the OSRF Gazebo and ROS 2 Jazzy apt repositories.
In addition to the runtime packages, building the pinned plugin required the
gz-sim headers, RapidJSON, OpenCV, and GStreamer development/plugin packages.
`mesa-utils` supplies the hardware-rendering check. ArduPilot's own Ubuntu
prerequisite installer remains required for its Waf/SITL toolchain.

```bash
sudo apt update
sudo apt install -y software-properties-common curl git git-lfs python3-venv python3-pip build-essential cmake ninja-build pkg-config mesa-utils
sudo add-apt-repository universe
sudo apt update
sudo apt install -y ros-jazzy-ros-base ros-dev-tools ros-jazzy-ros-gz
sudo apt install -y gz-harmonic libgz-sim8-dev rapidjson-dev libopencv-dev libgstreamer1.0-dev libgstreamer-plugins-base1.0-dev gstreamer1.0-plugins-bad gstreamer1.0-libav gstreamer1.0-gl
```

Create pinned, external checkouts (paths are examples and remain outside this
repository):

```bash
mkdir -p "$HOME/sim-src"
git clone --recurse-submodules --branch Copter-4.6.3 https://github.com/ArduPilot/ardupilot.git "$HOME/sim-src/ardupilot"
git -C "$HOME/sim-src/ardupilot" rev-parse HEAD
"$HOME/sim-src/ardupilot/Tools/environment_install/install-prereqs-ubuntu.sh" -y

git clone https://github.com/ArduPilot/ardupilot_gazebo.git "$HOME/sim-src/ardupilot_gazebo"
git -C "$HOME/sim-src/ardupilot_gazebo" checkout 082a0fe231f6e63bc8d1598f1cba461d9e2ea7f5
cmake -S "$HOME/sim-src/ardupilot_gazebo" -B "$HOME/sim-src/ardupilot_gazebo/build" -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo
cmake --build "$HOME/sim-src/ardupilot_gazebo/build" --parallel 4

cd "$HOME/sim-src/ardupilot"
./waf configure --board sitl
./waf copter
test -x build/sitl/bin/arducopter
cd -

python3 -m venv .venv-sim
source .venv-sim/bin/activate
python -m pip install --upgrade pip
python -m pip install MAVProxy pymavlink
```

Set the integration environment per terminal. No global shell edit is
required:

```bash
source /opt/ros/jazzy/setup.bash
source .venv-sim/bin/activate
export GZ_VERSION=harmonic
export ARDUPILOT_HOME="$HOME/sim-src/ardupilot"
export ARDUPILOT_GAZEBO_HOME="$HOME/sim-src/ardupilot_gazebo"
export GZ_SIM_SYSTEM_PLUGIN_PATH="$ARDUPILOT_GAZEBO_HOME/build${GZ_SIM_SYSTEM_PLUGIN_PATH:+:$GZ_SIM_SYSTEM_PLUGIN_PATH}"
export GZ_SIM_RESOURCE_PATH="$ARDUPILOT_GAZEBO_HOME/models:$ARDUPILOT_GAZEBO_HOME/worlds${GZ_SIM_RESOURCE_PATH:+:$GZ_SIM_RESOURCE_PATH}"
```

Build the existing EchoRescue ROS workspace separately when needed:

```bash
python -m pip install -e .
cd ros2_ws
colcon build --symlink-install
source install/setup.bash
cd ..
```

## Opt-in real-stack smoke test

Headless server mode:

```bash
./scripts/run_3d_integration.sh --output artifacts/v0.14-smoke.json smoke --mode headless --timeout 90
```

Native / WSLg graphical mode (first confirm `glxinfo -B` names the NVIDIA GPU,
not llvmpipe):

```bash
glxinfo -B
./scripts/run_3d_integration.sh --output artifacts/v0.14-smoke-gui.json smoke --mode graphical --timeout 90
```

The orchestrator starts the real `gz sim -r iris_runway.sdf` process (adding
server-only `-s` in headless mode), then real `sim_vehicle.py --no-rebuild`
with the JSON model and no MAVProxy child. Preflight requires the pinned
`build/sitl/bin/arducopter`; this keeps a first build, which can exceed the
runtime readiness timeout, outside the smoke test. It waits for the Gazebo
world topic and TCP 5760, receives a heartbeat, and explicitly requests
`MAV_DATA_STREAM_POSITION` at the configured baseline rate of 10 Hz before
sampling `GLOBAL_POSITION_INT` / `LOCAL_POSITION_NED`. Progress means a later
sample has a greater `time_boot_ms`; vehicle movement is not required.

The direct ArduPilot Gazebo plugin does not require ROS, so runtime ROS
node/topic inspection is reported `SKIP`; the diagnostic still requires the
selected ROS installation. A future ROS-backed configuration can list expected
nodes/topics in the same versioned contract.

Preflight failure returns `SKIP` (exit 2) and starts no process. Runtime
failure, timeout, premature exit or interruption returns `FAIL` (exit 1).
Owned process groups receive TERM and then KILL after the cleanup grace period;
the JSON result reports every owned root process as stopped. On runtime failure,
up to 64 KiB from the tail of each created Gazebo/SITL log is retained beside
`--output` as `<report-stem>.gazebo.log` and
`<report-stem>.ardupilot_sitl.log`; the report's `logs` entries name the exact
paths and whether truncation occurred. Successful-run temporary logs are
deleted.

During bring-up, heartbeat alone was insufficient: this Copter configuration
did not emit position packets until the position data stream was requested.
The initial automation therefore timed out despite a working TCP/MAVLink link.
Manual validation isolated the missing request and also showed that stationary
position packets advance `time_boot_ms`, which is the appropriate liveness
signal for this non-flight baseline.
