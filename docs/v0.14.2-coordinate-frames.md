# v0.14.2: Coordinate frames and continuous 3D vehicle state

## Scope

v0.14.2 extends the receive-only v0.14.1 path with one explicit conversion
boundary and one typed output:

```text
ArduPilot LOCAL_POSITION_NED + optional ATTITUDE / heading / landed state
  -> ROS-independent ContinuousStateAssembler
  -> echorescue_interfaces/msg/EchoRescueVehicleState3D
  -> /echorescue/vehicle/state_3d
  -> independent telemetry_observer process
```

The existing native MAVLink topics remain unchanged. The bridge still sends
only `REQUEST_DATA_STREAM(MAV_DATA_STREAM_POSITION)` and contains no vehicle
command API.

## Coordinate contract

| Quantity | ArduPilot source | EchoRescue output |
| --- | --- | --- |
| World frame | `mavlink/local_ned` | `echorescue/world_enu` |
| Position | north, east, down | `x=east`, `y=north`, `z=-down` |
| Velocity | north, east, down | `vx=east`, `vy=north`, `vz=-down` |
| Body frame | `mavlink/body_frd` | `echorescue/body_flu` |
| Body vector | forward, right, down | forward, `-right`, `-down` |
| Heading | degrees clockwise from north | degrees CCW from east, `[-180,180)` |
| Attitude | ZYX, NED world / FRD body, radians | ZYX, ENU world / FLU body, `[-pi,pi)` |

Full attitude is converted by changing both world and body bases, not by
renaming Euler components. This gives a level, north-facing FRD vehicle an ENU
yaw of `pi/2`. Round-trip property tests compare representative vectors,
headings, and nonsingular attitudes.

## Origin and time contracts

Local NED is authoritative. The configured origin policy is
`ardupilot_local_ned_at_sitl_startup`: EchoRescue ENU zero is ArduPilot's
startup-local zero with converted axes. Global WGS84 remains metadata and never
replaces local coordinates. No GPS-to-local projection exists.

Each converted state contains:

- vehicle, MAVLink session, system and component identity;
- MAVLink packet and accepted bridge sequences;
- local-position `source_time_boot_ms` (vehicle time);
- `receipt_monotonic_ns` (host receipt time), which is never interpreted as
  vehicle time;
- separate source boot times for optional attitude and heading;
- explicit source/output world and body frames and origin/angle policies;
- position, velocity, optional attitude/heading, armed, optional landed state,
  telemetry health, and validity indicators.

Duplicate/decreasing local source times are rejected within a session. A new
heartbeat session clears cached attitude, heading, landed state, and the prior
source timestamp. Observers require advancing samples within one session; a
reconnect cannot make a lower reboot time appear to advance an older session.
The integration observer names both clock domains and requires both the vehicle
boot clock and host monotonic receipt clock to advance independently; it never
compares differently scaled absolute values.

## ROS contract and QoS

`/echorescue/vehicle/state_3d` uses
`echorescue_interfaces/msg/EchoRescueVehicleState3D` with the same best-effort,
volatile, keep-last-32 QoS as native high-rate telemetry. The message header is
stamped at local ROS receipt/publication time and names the output ENU frame;
the explicit monotonic receipt field remains the ordering clock used by the
domain boundary.

No TF is emitted because the absolute relationship between the ArduPilot EKF
startup origin and Gazebo world origin is not verified. Publishing one would
invent a transform.

## Configuration and execution

The machine-readable contract is
[`config/coordinate-frames-v0.14.2.json`](../config/coordinate-frames-v0.14.2.json).
It configures vehicle ID, world/body frame names, angle convention, origin
policy, MAVLink endpoint, stream/freshness thresholds, typed topic inventory,
and independent observer.

After preparing the native Ubuntu 24.04/Jazzy environment documented for
v0.14.0/v0.14.1, build the ROS workspace and run:

```bash
./scripts/run_coordinate_frames_integration.sh \
  --output artifacts/v0.14.2-coordinate-smoke.json \
  smoke --timeout 90
```

The report contains counts and first/last source times for both native NED and
converted ENU samples, an independent same-session/time comparison of position
and velocity axes, a separate local receipt timestamp, frame/value examples,
health checks, retained failure-log paths, and every process/port cleanup gate.
Stationary telemetry is valid when source time advances. Movement or orientation
differences are reported only if actually observed; the harness sends no flight
command to create them.

## Ground Truth and determinism

The runtime bridge and conversion core import no Gazebo API and subscribe to no
Gazebo world/model/pose topic. Gazebo is used by the outer process harness only
to establish that the real Iris simulation is live. Autonomous EchoRescue logic
receives no Gazebo Ground Truth.

The deterministic grid core is untouched. Exact existing fingerprints remain
suite gates. Real physics, ROS receipt times, and process IDs are evaluated with
event/ordering invariants rather than byte equality.

## Validated native result

On the audited native Ubuntu 24.04/Jazzy machine, the final 90-second headless
run received two native local-NED samples and two converted ENU samples with
source boot time advancing from 2001 to 2101 ms. The independent observer saw
`north=0`, `east=0`, `down=-0.19 m` become `x=0`, `y=0`, `z=+0.19 m` and
reported the velocity as stationary. It independently matched both NED/ENU
position and velocity pairs and received a valid converted heading of 90.81
degrees. No movement or attitude-change validation is claimed.

`ATTITUDE` and `EXTENDED_SYS_STATE` were not present before the observer
completed, so `has_attitude=false` and `has_landed_state=false`; no zero value
was treated as valid. Telemetry age was 0.059313 s against a 1.0 s threshold.
Gazebo, SITL, bridge and observer cleanup passed, and UDP 9002/14550 plus TCP
5760 were available afterward. The v0.14.1 native-topic regression separately
passed with three advancing NED samples (2021 to 2221 ms) and the same seven
cleanup gates.

## Limitations

- Receive-only state is not a flight command, localization solution, or safety
  claim.
- There is no GPS projection, verified Gazebo-to-EKF transform, TF, sensor
  fusion, navigation, obstacle avoidance, SLAM, indoor world, perception,
  multi-vehicle, HIL, or real-flight support.
- Attitude and landed state depend on optional MAVLink messages and carry false
  validity indicators until observed.
- Validation may be stationary because this milestone deliberately sends no
  arming, takeoff, mode, waypoint, or motion command.
