# v0.14.3: Simulation-only arm–takeoff–hover–land milestone

## Scope and architecture

v0.14.3 implements one bounded single-Iris simulation mission:

```text
Gazebo Harmonic iris_runway <-> ArduPilot Copter SITL
                                      |
                                      | MAVLink telemetry + bounded commands
                                      v
                    echorescue_mavlink_flight_mission
                         | typed ROS 2 telemetry topics
                         v
                    flight_mission_observer
```

The existing `mavlink_telemetry_bridge` executable remains receive-only. The
new runner is the only command-capable process. It imports no Gazebo API and
uses ArduPilot heartbeat, local NED position converted to ENU-up, telemetry
health, `EXTENDED_SYS_STATE`, and `COMMAND_ACK` as its only control evidence.
The command executable rejects serial, UDP, and non-loopback endpoints; this
milestone accepts only a loopback TCP SITL transport.

## Command and transition contract

| Phase | MAVLink command | Required ACK | Required later telemetry |
| --- | --- | --- | --- |
| Telemetry setup | `MAV_CMD_SET_MESSAGE_INTERVAL(EXTENDED_SYS_STATE)` | `MAV_RESULT_ACCEPTED` | an `EXTENDED_SYS_STATE` sample |
| Mode | `MAV_CMD_DO_SET_MODE(GUIDED)` | `MAV_RESULT_ACCEPTED` | heartbeat mode is `GUIDED` |
| Arm | `MAV_CMD_COMPONENT_ARM_DISARM(1)` | `MAV_RESULT_ACCEPTED` | heartbeat has armed flag |
| Takeoff | `MAV_CMD_NAV_TAKEOFF` | `MAV_RESULT_ACCEPTED` | `-LOCAL_POSITION_NED.z` reaches configured ENU altitude band |
| Land | `MAV_CMD_NAV_LAND` | `MAV_RESULT_ACCEPTED` | landed state is `ON_GROUND` and a later heartbeat is disarmed |

Only one command is outstanding at a time. Unexpected, stale, or wrong-command
ACKs do not advance the mission. `MAV_RESULT_IN_PROGRESS` is recorded but does
not replace the required final accepted ACK. No implicit disarm command is
sent: ArduPilot's LAND behavior performs auto-disarm, which must be verified
independently through heartbeat telemetry.

The configured `target_altitude_enu_m` is local up from ArduPilot's startup
local origin, matching the v0.14.2 `echorescue/world_enu` origin policy. It is
passed as the guided takeoff altitude and independently checked after converting
local NED down to ENU up. Gazebo pose is never queried or used as feedback.

## Failure, reconnect, and cleanup behavior

- Stale or disconnected telemetry aborts normal flight progression.
- A rejected command or a missing ACK/state transition times out the phase.
- A MAVLink session change aborts the mission; observations never cross
  sessions.
- If arm state may be true or is uncertain after an issued arm command, cleanup
  waits for a fresh post-failure heartbeat. Armed state enters the LAND recovery
  path; confirmed disarmed state ends safely as a failed mission.
- Recovery LAND has its own accepted ACK and later landed/disarmed telemetry
  requirements. Cleanup time is bounded and an unverified recovery stays FAIL.
- LAND is issued at most once per MAVLink session, so an ACK delayed by stale
  telemetry cannot be mistaken for a newer LAND command. A new recovery LAND
  is permitted only after an observed reconnect creates a new session.
- The orchestration harness owns only the process groups it starts, retains
  bounded failure-log tails, and checks all configured ports after teardown.

## Configuration and execution

The versioned contract is
[`config/flight-mission-v0.14.3.json`](../config/flight-mission-v0.14.3.json).
Defaults are 2.0 m ENU altitude, ±0.35 m takeoff threshold, three seconds of
hover, a 30-second fresh/disarmed preflight hold, one-second telemetry
freshness, and bounded ready/transition/takeoff/landing/cleanup timers.

After building and sourcing the Jazzy workspace and exporting the v0.14.0
ArduPilot/Gazebo environment:

```bash
./scripts/run_flight_mission_integration.sh diagnose
./scripts/run_flight_mission_integration.sh \
  --output artifacts/v0.14.3-flight-smoke.json \
  smoke --timeout 150
```

The smoke report passes only when the mission report contains exactly the
extended-state setup followed by GUIDED, arm, takeoff and land, every command
has an accepted ACK, every command has a matching telemetry transition received
strictly after that ACK, the final state is landed/disarmed, the independent
ROS observer passes in one
session, and all owned processes and ports clean up.

## Explicit exclusions

This milestone provides no waypoint navigation, horizontal motion target,
velocity control, obstacle avoidance, indoor environment, mapping integration,
multi-drone support, HIL, hardware flight, or v0.14.4 work. It is a simulation
integration milestone, not a general flight-safety claim.
