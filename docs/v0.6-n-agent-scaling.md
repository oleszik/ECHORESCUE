# v0.6 — N-Agent Scaling

## Motivation and scope

EchoRescue historically exposed one- and two-drone execution paths. v0.6 asks
how the existing deterministic SAR coordination scales when 1, 2, 4, and 8
agents use one simulation core. The experiment deliberately keeps the map,
Visual sensor, Smoke-off setting, Relay-off strategy, and no-failure baseline
fixed. It does not add new perception, fusion, Relay, failure, dynamic-world,
or multi-floor behavior.

## Inventory and generalization

The audit found that frontier assignment, communication graphs, map merging,
energy state, return-to-base state, failure-task ownership, event collections,
and most result metrics were already collection-based. The remaining fixed
assumptions were the 1/2 configuration gate, two fixed start cells, CLI and
failure-ID validation, two-map divergence, a two-intent distributed conflict
path, replay generation guards, terminal symbols, and two static dashboard
cards/map selectors.

The implemented architecture uses `MultiDroneSimulation` for every supported
fleet size. IDs are generated as `drone-1` through `drone-N`; configuration
supports 1–8 agents. Default starts are the nearest free interior cells ordered
by distance from base, row, and column. Explicit shared-base starts remain
valid because the base is a virtual multi-vehicle dock. Non-base starts must be
unique.

The existing deterministic greedy allocator remains the only allocator. It
preserves valid targets, ranks reachable candidates by path length, target
coordinates, and agent ID, assigns at most one distinct target per agent, and
leaves excess agents idle. In the deterministic Visual/Smoke-off baseline, a
detected but not yet confirmed Survivor becomes a final revisit target before
exploration can complete. Smoke/Thermal miss semantics remain unchanged.

The central movement shield evaluates all active IDs, all agent pairs, current
cell occupancy, edge swaps, and arbitrary many-to-one convergence. Stable IDs
resolve a multi-contender vertex conflict. Cyclic occupied-cell moves are all
held. Active-local fleets larger than two use the same fleet-wide resolver as
their deterministic local conflict intervention; the established two-agent
intent/reservation protocol is retained unchanged for regression compatibility.
FAILED agents remain static blockers and are excluded from new assignments.

Replay frame and metric structures were already ID-keyed collections, so no
schema change was necessary. Existing schema versions remain valid. The
dashboard now creates local-map options, telemetry cards, paths, targets,
labels, and colors from the replay's agent collection. Its deterministic
eight-color palette cycles only beyond the currently validated maximum.

## Benchmark method

The committed artifact is
[`n_agent_scaling_50_seeds.json`](../benchmarks/n_agent_scaling_50_seeds.json).
For each fleet size, seeds 0–49 use the default 21×13 world, Visual Survivor
sensor, Smoke off, shared knowledge, ideal communication, Relay off, no injected
failure, and identical energy limits. Every seed/fleet pair is run twice and
compared for deterministic equality: 400 executions produce 200 measured
primary results. Standard deviation is the population standard deviation.

Reproduce it with:

```bash
python -m echorescue.scaling_benchmark --seeds 50 \
  --output benchmarks/n_agent_scaling_50_seeds.json
```

## Interpretation and per-seed regressions

Two agents provide the dominant gain: 49.42 fewer mean steps. Doubling to four
saves only 6.74 further steps, and doubling again saves 3.32. Parallel
efficiency therefore falls from 0.843 at two agents to 0.465 at four and 0.245
at eight. Useful first detection continues to improve, but total fleet travel,
overlap, and interventions grow sharply. The current greedy strategy visibly
saturates between four and eight agents on this map size.

More agents are not uniformly faster. No 2-agent run was slower than its
1-agent counterpart. Four agents were slower than two on 14/50 seeds; seed 3
is representative (60 versus 74 steps, 34.09% overlap, three interventions).
Eight agents were slower than four on 15/50 seeds; seed 9 is representative
(56 versus 66 steps, 55.83% overlap, eight interventions). These telemetry
patterns support coordination contention and redundant coverage as the likely
causes; the baseline recorded no replans, so replanning is not the explanation.

## Demo, limitations, and next question

The four-agent demo is
[`seed_44_4_agents.json`](../replays/seed_44_4_agents.json). It completes in 68
steps with three Survivor confirmations, four safe returns, five deterministic
movement interventions, and zero collisions:

```bash
python -m echorescue.dashboard \
  --replay replays/seed_44_4_agents.json \
  --benchmark benchmarks/n_agent_scaling_50_seeds.json
```

Adaptive and Network-aware Relay retain their validated two-agent Scout/Relay
semantics and configuration rejects larger Relay-enabled fleets. Generalized
roles and multi-Relay routing belong to v0.10. Advanced distributed reservation
telemetry also remains richer for the retained two-agent protocol; fleet-wide
safety itself is generic. Benchmark aggregation modules remain outside the
current mypy gate, while every changed production module is checked.

The next research question is not whether more agents can run, but which
fleet-aware allocation cost can reduce overlap and contention without losing
determinism. v0.7 Noisy Perception and Confidence is intentionally not started
by this slice.
