# v0.14.5 indoor reference world

## Scope

v0.14.5 validates one predefined collision-free route in one small,
simulation-only Gazebo world. It reuses the v0.14.4 controller and its
same-session telemetry, progress, 3D arrival, settling, geofence, timeout and
bounded LAND recovery semantics. It adds no planning, sensing, avoidance,
SLAM, exploration, survivor behavior, dynamic obstacle, global navigation,
multi-drone or vehicle support.

## Reproducible geometry and route

[`config/indoor-reference-v0.14.5.json`](../config/indoor-reference-v0.14.5.json)
is the numeric authority and
[`worlds/echorescue_indoor_v0_14_5.sdf`](../worlds/echorescue_indoor_v0_14_5.sdf)
is the matching primitive SDF. The 12 x 8 x 4.5 m shell has a divider at world
x=0, a 2.4 m wide by 3.2 m high doorway, and a 1.5 x 2.0 x 2.4 m blocker at
(2.5, 0, 1.2). The Iris launches at world ENU (-4, 0, 0.195).

The ordered launch-relative ENU targets are:

| Target | East | North | Altitude above launch |
| --- | ---: | ---: | ---: |
| launch-stabilize | 0.0 | 0.0 | 1.5 |
| door-approach-outbound | 3.2 | 0.0 | 1.5 |
| doorway-outbound | 4.8 | 0.0 | 1.5 |
| obstacle-bypass-outbound | 4.8 | 2.0 | 1.5 |
| far-room | 8.0 | 2.0 | 2.2 |
| obstacle-bypass-return | 4.8 | 2.0 | 1.5 |
| doorway-inbound | 4.8 | 0.0 | 1.5 |
| door-approach-return | 3.2 | 0.0 | 1.5 |
| return-launch | 0.0 | 0.0 | 1.5 |

The direct launch-to-far-room segment intersects the blocker. The configured
route instead has at least 0.55 m nominal center clearance: 0.35 m conservative
vehicle radius plus 0.20 m margin. Configuration validation checks every
segment against every solid before launch.

## Control and evaluation boundary

```text
configured targets -> v0.14.4 mission -> MAVLink commands -> ArduPilot
                            ^                                  |
                            +------ MAVLink telemetry ----------+

Gazebo pose + per-solid contacts -> independent evaluator -> acceptance only
                                                        \-> fail/interrupt run
```

The mission never reads Gazebo state. The evaluator never supplies control.
On collision, the harness interrupts route execution; the mission then uses
the existing bounded telemetry-gated LAND recovery. See [ADR 0020](adr/0020-telemetry-control-gazebo-evaluation-separation.md).

All ten solids have explicit contact sensors. Accepted zero-contact evidence
requires all ten topics to exist, no prohibited contact messages, no
conservative-radius intersection, two ordered doorway crossings, entry into
the far-side region and return to the launch region. Floor contact is allowed
only in the configured launch/landing region below the configured center
height. Clearance is sampled at 10 Hz and is not a full swept-volume proof.

## Commands

After the [v0.14.0 environment setup](v0.14-3d-integration-baseline.md), build
and source the Jazzy workspace. Diagnose with:

```bash
./scripts/run_indoor_reference_integration.sh diagnose
```

For a visible demonstration owned by one EchoRescue command (no MAVProxy
commands or manual vehicle control):

```bash
./scripts/run_indoor_reference_integration.sh \
  --output artifacts/v0.14.5-indoor-graphical-owned.json \
  smoke --stack-mode owned --graphical --timeout 260
```

The same `smoke --stack-mode attached --graphical` path is supported when the
exact indoor Gazebo world and pinned SITL are already visible; it owns only the
mission, observer and evaluator and preserves the external stack.

Final lifecycle acceptance owns every process:

```bash
./scripts/run_indoor_reference_integration.sh \
  --output artifacts/v0.14.5-indoor-headless-owned.json \
  smoke --stack-mode owned --timeout 260
```

The deliberate controlled-contact test is:

```bash
./scripts/run_indoor_reference_integration.sh \
  --output artifacts/v0.14.5-indoor-negative-collision.json negative-collision
```

## Acceptance evidence

All three September 11, 2026 reports are `PASS`:

- [`artifacts/v0.14.5-indoor-graphical-owned.json`](../artifacts/v0.14.5-indoor-graphical-owned.json)
  records the inspected visible run. The small two-room shell, doorway, orange
  blocker and airborne Iris were clear in Gazebo; all nine targets completed.
- [`artifacts/v0.14.5-indoor-headless-owned.json`](../artifacts/v0.14.5-indoor-headless-owned.json)
  is the final lifecycle acceptance. Its single MAVLink session reached 2.44 m
  maximum ENU altitude and 8.333 m maximum horizontal displacement, returned
  to 0.109 m from launch, then reported `ON_GROUND` and disarmed. Both doorway
  crossings were inside the opening. Evaluated obstacle surface clearance was
  0.509 m after subtracting the 0.35 m vehicle radius; doorway-boundary surface
  clearance was 0.842 m. All ten contact topics were present, the only counted
  contact was allowed launch-floor contact, and no prohibited contact occurred.
  Every process, both ROS nodes and UDP 9002/14550 and TCP 5760 were absent or
  free after cleanup.
- [`artifacts/v0.14.5-indoor-negative-collision.json`](../artifacts/v0.14.5-indoor-negative-collision.json)
  records a controlled teleport into the blocker. The actual obstacle contact
  sensor named the colliding Iris components, the evaluator exited failed as
  required, and the negative test passed only because that failure and full
  cleanup were observed.

Reports retain exact pinned source revisions and separate mission, independent
ROS observer and Gazebo evaluation sections. The final Python suite passed 463
tests; 13 native Jazzy tests passed separately. Jazzy build, mypy, compileall,
JSON/XML validation, shell syntax and diff hygiene also passed.

## Limitations

- The evaluation-only world-to-launch relation is a comparison, not mission
  localization. A reconnect while airborne fails the route and lands.
- Static AABBs and a conservative sphere approximate geometry; rotor swept
  volume, aerodynamics and real construction tolerances are not proven.
- The fixed route is intentionally tailored to this versioned world. It does
  not discover or avoid obstacles.
- This is simulation-only evidence and must not be used for a real vehicle.
